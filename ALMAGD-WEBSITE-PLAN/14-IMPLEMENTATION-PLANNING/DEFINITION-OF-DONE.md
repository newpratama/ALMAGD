# تعريف الإنجاز

إنجاز الوثائق، وإنجاز المهمة البرمجية، وإنجاز الإطلاق حالات مستقلة؛ لا تتبادل في التقارير.

## وثيقة منجزة

- Markdown باسم ومكان صحيحين، تربط مصادرها و DEC/F/MD ذات الصلة.
- توضح النطاق والمتطلبات والقبول والبيانات الناقصة دون اختراع.
- روابط وأسماء و IDs سليمة، ولا code أو ملفات موقع.
- لا تعديل للأساس؛ تفرق التخطيط من approvals واختبارات runtime.

## مهمة تنفيذ منجزة لاحقاً

- T-ID و ownership واضحان، تنفيذ spec دون إعادة تصميم.
- نصوص وصور وحقائق من المصدر، gates مفعلة و dev markers صريحة.
- التحقق المناسب للمتأثر مكتمل؛ FAIL مصحح مع retest، و NOT_RUN لا يسمى PASS.
- RTL و keyboard والاستجابة والحالات المطلوبة تعمل؛ بناء static يمر.
- تقرير changed/why/evidence/blockers، لا إعلان launch من مكون واحد.

## إطلاق منجز لاحقاً

- PRE-LAUNCH-CHECKLIST و AC المطلوبة لها أدلة؛ بوابات MD مغلقة أو استثناء مسموح.
- حقوق وتراجم ومراجعة قانونية مكتملة و 0 Critical/High.
- نسخة مراجَعة مع اعتماد إطلاق، و production smoke/robots/canonical/contact سليمة.
- مسؤول MD-75 و rollback والصيانة موثقة؛ analytics بعد consent وحسابات المالك مأذونة.

field CWV يحتاج زيارات فعلية؛ عند غيابها يسجل monitoring pending لا p75 PASS. نجاح lab لا يلغي هدف field بالعقد.

حالياً: التخطيط مكتوب وجاهز للمراجعة والتسليم مع نواقص واضحة؛ التنفيذ NOT_STARTED،runtime QA NOT_RUN،الإطلاق BLOCKED. إكمال المواصفات لا يعني استلام الصور أو موافقة المراجعين.
