# خارطة التنفيذ اللاحق

DEC-030؛ الوثائق الحالية تخطيط فقط. ترتيب phase 0–12 يتيح للنموذج البرمجي تنفيذ مهمة صغيرة محددة بعقد ثابت؛ لا إذن بالتنفيذ الآن. التفاصيل في [TASK-BREAKDOWN](./TASK-BREAKDOWN.md).

| Phase | الناتج | بوابة الانتقال |
|---|---|---|
| 0 | تثبيت العقد والبيانات والتحقق من الإصدارات | طلب تنفيذ مستقبلي صريح؛ سجل فجوات P0 |
| 1 | مشروع static وعقود تحقق المحتوى | IDs وحالات الحقائق ثابتة |
| 2 | tokens والخطوط والمكونات الأولية | التباين و RTL والاستجابة |
| 3 | layouts والتنقل واللغة و consent | الروابط سليمة ولا تعقب قبل الموافقة |
| 4 | Home و About و Properties | تعريف محايد للمجموعة دون قصة مختلقة |
| 5 | صفحتا الإقامة والغرف | حقائق معتمدة وتوجيه WhatsApp/OTA صحيح |
| 6 | Cafe و Menu | سجل 47 محفوظ وحالات HOLD محجوبة |
| 7 | Gallery والميديا | حقوق و alt وصور متجاوبة |
| 8 | Location و Contact | pins وأرقام مؤكدة؛ لا forms |
| 9 | Privacy و 404 و SEO | مراجعة قانونية و canonical و status صحيحان |
| 10 | GA4 والأحداث | consent وغياب PII ومنع الازدواج |
| 11 | QA وإصلاحات ما قبل الإطلاق | أدلة الفحوص و 0 Critical/High |
| 12 | preview والمراجعة والنشر والصيانة | إغلاق البيانات والتراجم والحقوق واعتماد الإطلاق |

## مسارا التنفيذ والبيانات

يمكن تطوير layout مع PLACEHOLDER في dev فقط بعد طلب coding مستقبلي؛ جمع بيانات الإدارة والحقوق والتراجم يستمر مستقلاً. لا يلزم انتظار سعر Es Kopi لتصميم القائمة، لكن موقع Cafe وساعاته بوابات إطلاق حقيقية. لا يخفض النموذج نطاق الإطلاق أو يحل تعارض حقائق من تلقائه.

مهمة واحدة → قراءة العقد و spec → تعديل الملفات المحددة → تحقق مناسب → تقرير النتيجة والقيود → المهمة التالية. فشل التحقق يمنع إعلان إنجاز المهمة حتى إصلاحه. يمكن مواصلة مهمة مستقلة عن blocker دون الادعاء أن الموقع جاهز.

P1: FAQ مستقلة، محرر Git عند الحاجة، فيديو desktop اختياري. P2: Offers بعد عرض حقيقي. لا blog أو URLs غرف أو محرك حجز ضمن الخطة. مواعيد وأتعاب التنفيذ PLACEHOLDER لأن الفريق والأصول لم يحددا؛ لا موعد إطلاق مختلق.

قبول الخطة: مراحل 0–12، تبعيات واضحة، بوابات بيانات محفوظة، ومهام ذرية يمكن مراجعتها. كل مراحل التنفيذ حالياً NOT_STARTED.
